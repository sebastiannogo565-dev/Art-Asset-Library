## 4. 预览和Enter的三维兼容方式

当前源码 `SchoolLifeWorldSubsystem.cpp:72–88` 在230cm球内选最近有效 PlaceActor；`SchoolLifeWorldActivityConfirmation.cpp:88–101、182–205` 分别预览、重验同一意图与当前身份/资格，Enter再次检查实际 Actor—A 的完整三维距离。

采用 `d=√((ActorX−AX)²+(ActorY−AY)²+(ActorZ−AZ)²)`，余量 `230−d`。预览P、确认E各算一次，均须非负且身份/所选PlaceId/业务资格有效；地面G、贴图中心、椅中心和导航N均不替代 Actor/A。只到230cm以内不代表资格通过；E还需避免区域出口优先分支抢占。

|明确条件算例（不是运行测量）|P与E分别的距离|各自余量|
|---|---:|---:|
|F2 G.Z=1200；Actor高出96；A候选Z=1200，同XY|96cm|+134cm|
|同上，Actor高出98cm的helper示例|98cm|+132cm|
|G.Z=1200；Actor高出96；若A仍历史Z=800，同XY|496cm|−266cm|
|同上，Actor高出98cm的helper示例|498cm|−268cm|

在96cm竖差的条件例中，水平可用半径约209.01cm（√(230²−96²)），不是平面230cm；实际值须用实际竖差重算。若仍保800锚点而人在正式F2，最优水平重合也超出266/268cm，不能靠换席解决。推荐取舍是**未来经批准统一二层锚点/导航/楼层接口，保留楼层、人物和230cm**，不是现在抬锚点或降低建筑。

构造 `InitCapsuleSize(34,96)` 仅是默认值；98cm只来自部分落地helper的“半高+2”，不宣称所有站立状态都额外+2。需原生读 actual scaled 半高、实际Actor及脚下命中。胶囊底 `ActorZ−scaled半高` 也不等于地面命中实测。

不要求门口到操作处全过程或19阶段全过程都在交互球内；只按原预览与确认时机核验。不新增“先坐下”课堂启动条件，不默认传送，不删除自身椅子或缩人物来达标。G候选与最终玩家席是两项问题，本方案不宣布完整入座、全部30席或整栋最终通过。
